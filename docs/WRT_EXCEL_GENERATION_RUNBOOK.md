# WRT_HELPER Excel版 正本生成手順書

更新日: 2026-08-29  
対象成果物: `WRT_HELPER-ver1.20.xlsm`

## 1. 正本

- 入力ブック: `WRT_HELPER-ver1.19R1_SOURCE.xlsm`
- 入力SHA-256: `3b9f795388ae8f9312fe8886c9259a09494cce40f9d21fbce3d97b67d777e352`
- VBA正本: `Module1_ver1.20.bas`
- VBA SHA-256: `c7f0ded228fde1a6f19914e0e623d5e31d486bb61c2fae0628532c54f56cfa1d`
- 生成スクリプト: `BUILD_AND_VERIFY.js`
- 実行入口: `RUN_BUILD.bat`

この4点以外から想像で再構築しない。別チャットでも、最初に入力ブックとVBA正本のSHA-256を照合してから生成する。

## 2. 固定生成方式

1. 入力xlsmをbyte-for-byteでLocalAppDataの一時フォルダへコピーする。
2. Windows版Excel COMで一時コピーを開く。
3. OOXMLの再保存、LibreOffice変換、Pythonによるxlsm再構築は行わない。
4. `VBProject.VBComponents("Module1").CodeModule`を取得する。
5. Module1を部分置換せず、`Module1_ver1.20.bas`の全文で一括置換する。
6. 保護された`01_受付画面`を生成スクリプトから直接編集しない。
7. VBA内の公開マクロだけで受入試験と最終クリーンを行う。
8. 全GateがPASSした場合だけ、`WRT_HELPER-ver1.20.xlsm`として保存する。
9. FAIL時は出力xlsmと成功証跡を削除し、完成扱いにしない。
10. 実行後、`AccessVBOM`レジストリ値を実行前の状態へ戻す。

## 3. 今回の仕様修正

### 複数製品の末尾に水栓が混入する問題

原因は、明示されたシリーズ候補を取得した後も、案件全文中のマスタ語句を追加検索していたこと。製品情報外の注意書き等にある「水栓」が候補へ追加される可能性があった。

修正後:

- 候補検索対象を`ProductSectionTextV020(fullText)`へ限定。
- 「シリーズ」等の明示候補が1件以上あれば、それだけを候補正本とする。
- マスタ語句検索は明示候補が0件の場合だけ実行。
- 製品情報外へ「シリーズ：水栓」を置いた回帰ケースで、候補が2件のまま、水栓が0件であることを確認。

### 回線未選択時の取込

- `SELECTED_LINE`が空欄だけでなく、回線マスタに存在しない無効値の場合も未選択扱いにする。
- 取込を実行せず、案件本文を変更しない。
- 画面下部、取込状態、回線案内をオレンジ表示にする。
- `MsgBox`で「左の入電回線を選択してから再度取込」と明示する。
- 起動時は保存値にかかわらず回線未選択へ戻す。

### コピー・取込ボタンの反応

成功時に1200msだけボタンを緑色へ変え、次を表示する。

- 取込: `✓ 取込済み`
- 全文コピー: `✓ コピー済み`
- 4項目履歴コピー: `✓ 4項目コピー済み`
- 通話メモコピー: `✓ コピー済み`

元のボタン色・文言は自動で復元する。自己診断中はフラッシュを抑止する。

## 4. 必須Gate

生成スクリプトは次を順番に検査する。

1. 入力ブックSHA一致
2. Module1正本SHA一致
3. Module1全文置換成功
4. 重要ソースアンカー存在
5. `WRT_PatchGateV021 = PASS`
   - 明示2製品のみ
   - 製品情報外の水栓候補0件
   - 複数製品の自動選択なし
   - 回線未選択案内登録済み
6. `WRT_TestAttachedPlanCandidatesV120 = PASS`
   - 付属プラン10件を順番どおり候補化
   - 多機能便座2件と24時間換気2件を別候補として保持
   - 1件目を自動選択しない
7. `WRT_SelfTest`
   - `PASS / PASS=200 FAIL=0`
8. 最終クリーン
   - 回線未選択
   - 案件本文空欄
   - WORK候補残留なし
9. xlsm保存成功
10. 出力byte size・SHA-256記録

## 5. 禁止事項

- ソースアンカーを推測して部分パッチを重ねること
- 保護シートへ生成スクリプトから直接書き込むこと
- 既存の成功ファイルをOOXMLライブラリで再保存すること
- 実機Gate未通過のファイルを「完成」と呼ぶこと
- FAILのたびに別名ZIPを増やし、原因を固定しないまま再試行すること
- 旧ZIPや旧Module1を新しい正本として流用すること

## 6. 別チャットでの再生成

別チャットでは次の順で進める。

1. この手順書を開く。
2. 入力ブック、Module1、生成スクリプト、manifestの4点を取得する。
3. SHA-256を照合する。
4. 変更要求がある場合はModule1正本だけを更新する。
5. 新しいModule1のSHAと変更内容をmanifestへ記録する。
6. `RUN_BUILD.bat`で1回生成する。
7. Gateのログ、出力bytes、SHAを保存する。
8. PASS成果物とこの手順書を同時に引き継ぐ。

## 7. 失敗時に必要な証跡

- `WRT_HELPER-ver1.20_BUILD_LOG.txt`
- 画面に表示された最初のFAILED行
- 入力ブックSHA
- Module1 SHA
- Excelのバージョン

ログなしで新しいZIPを作らず、最初のFAILED Gateだけを修正する。

## ver1.20 追加修正

- 複数製品候補は `WORK!D` の表示残りではなく、内部レコード `gProductCaption()` を正本としてメニュー生成する。これにより候補リストの取りこぼしを防ぐ。
- 取り込みで複数製品が検出された場合、候補一覧をメッセージでも表示し、画面上部の `WRT_LINEINFO` にも展開する。
- コピー系ボタン（全文コピー / 4項目コピー / 通話メモコピー）は、短い点滅だけでなく `WRT_IMPSTATE` と `WRT_LINEINFO` に成功状態を表示する。
- 反応視認性を上げるため、ボタンの成功表示は 1200ms 保持する。

## 8. 生成スクリプトの文字コード固定（必須）

Windows Script HostのJScriptは、UTF-8 BOM付きファイルを1行目1文字目の不正文字として拒否する環境がある。今回の失敗を再発させないため、次を正本ルールとして固定する。

- `BUILD_AND_VERIFY.js` は **UTF-16LE（BOM付き）** で保存する。
- `BUILD_AND_VERIFY.js` の先頭6bytesは必ず `FF FE 2F 00 2F 00`（BOM + `//`）とする。
- `RUN_BUILD.bat` は **ASCII（BOMなし）** で保存する。
- `RUN_BUILD.bat` の先頭9bytesは必ず `40 65 63 68 6F 20 6F 66 66`（`@echo off`）とする。
- `EF BB BF`で始まるJS/BATはパッケージへ入れない。
- ZIP作成前に、実機で構文検査を通過した旧ビルダーと先頭16bytesを照合する。
- 構文の内容検査と文字コード検査は分離する。内容はNode等で検査し、最終配布JSはUTF-16LEへ戻す。
- 上記byte gateが不一致ならZIPを生成しない。

現行正本:

- 入力ブックSHA-256: `3b9f795388ae8f9312fe8886c9259a09494cce40f9d21fbce3d97b67d777e352`
- Module1 SHA-256: `c7f0ded228fde1a6f19914e0e623d5e31d486bb61c2fae0628532c54f56cfa1d`

- ver1.20の画面表示は、自己診断前にVBAの専用GateでB4へ反映し、再保護まで検証する。
- 自己診断がFAILした場合は、失敗行・項目・期待値・実値を黒い画面へ直接表示する。

## 9. ver1.20 付属プラン全件候補化（2026-08-29追加）

### 原因

`ProductSectionTextV020`が「製品情報」から`■プラン詳細`の直前までを候補抽出範囲としていたため、付属プラン10件のうち、製品情報側やマスタ検索で拾えた4件だけが候補になっていた。

### 修正

- `付属プラン`、`■プラン詳細`、`プラン詳細`のいずれかに「シリーズ」がある場合、そのセクションを候補抽出の正本にする。
- `【10年保証】`を含むプラン見出しを製品レコード境界として扱う。
- プラン見出しを各レコードの保証プラン名として保持し、`多機能便座(2)`と`24時間換気システム(2)`を重複削除しない。
- 候補メニューは内部レコード10件を順番どおり表示する。

### 必須Gate

`WRT_TestAttachedPlanCandidatesV120`で、次の10件を順番どおり検査する。

1. システムキッチン
2. 食器洗い乾燥機
3. システムバス
4. 洗面化粧台
5. 多機能便座
6. 多機能便座（2件目）
7. 24時間換気システム(セントラル)
8. 24時間換気システム(セントラル)（2件目）
9. 給湯器
10. ドアホン

Gateは、候補数10、各候補名、WORK保持、重複2件の保持、未選択状態を検査する。1つでも不一致なら出力xlsmを生成しない。
