# WRS引き継ぎ対象 保留メモ

作成日: 2026-06-06

## 目的

WRS引き継ぎ対象候補のうち、誤判定リスクがあり現時点では `data/master_wrs_handover_rules.csv` に追加しない対象を明文化する。後続作業で「未登録なのか、意図して保留しているのか」が分からなくなることを防ぐ。

このメモは仕様確認待ちの記録であり、判定ルール追加ではない。

## 保留対象

- 住設（賃貸・中古）
- 日新

## 住設（賃貸・中古）

### 保留理由

- 「住設」「賃貸」「中古」は語が広く、単独条件で拾うと通常の住設案件や賃貸系案件までWRS引き継ぎ対象になるリスクがある。
- どの項目で判定すべきか未確定。
  - 回線名
  - 保証プラン
  - 販売店
  - 運営会社
  - 案件区分
  - 製品分類
- WRS引き継ぎ条件として「日新」との関係確認が必要。

### 今後確認すべき条件

- 「住設（賃貸・中古）」は具体的にどの入力項目に現れるのか。
- WCS/保証管理画面上の正式表記。
- 日新案件だけが対象なのか。
- 住設かつ賃貸/中古なら全て対象なのか。
- 問い合わせと修理受付で扱いが違うのか。
- `action_type` は「受付報告」でよいのか。
- `note_template` に入れるべき注意文があるか。

### 追加する場合の想定ルール

- `match_appliance_type` に住設条件を置く場合は、必ず販売店・運営会社・保証プラン・案件区分などの明確な identity 条件と組み合わせる。
- 「賃貸」「中古」だけを `match_plan_keywords` や `match_case_keywords` に入れる場合は、通常案件への誤爆を避けるため、日新などの固有条件とセットにする。
- 受付報告以外の依頼種別がある場合は、`action_type` を業務確認後に設定する。

### 誤判定リスク

- 通常の住設案件が、賃貸物件・中古住宅などの文脈だけでWRS引き継ぎ対象になる。
- 保証プランやメモに「賃貸」「中古」が含まれるだけで対象化する。
- 問い合わせ一次受けと修理受付を混同する。

## 日新

### 保留理由

- 単独会社名として追加すると、日新という文字列を含む別会社/別案件に誤爆する可能性がある。
- 「住設（賃貸・中古）」とのセット条件なのか、日新単独条件なのか未確認。
- `master_vendor_rules.csv` 側の扱いと WRS引き継ぎ対象の扱いを混同しない必要がある。

### 今後確認すべき条件

- 正式会社名。
- 販売店名/運営会社名/保証プランのどこに出るか。
- 日新の全案件がWRS引き継ぎ対象か。
- 住設/賃貸/中古に限定されるか。
- 問い合わせ一次受けも対象か、修理受付のみか。

### 追加する場合の想定ルール

- 日新単独が対象なら、正式表記と表記揺れを確認して `match_store_keywords` または `match_company_keywords` に追加する。
- 住設（賃貸・中古）限定なら、日新の identity 条件に加えて `match_appliance_type` や保証プラン/案件区分の条件を併用する。
- `master_vendor_rules.csv` の修理依頼先判定とは別に、WRS引き継ぎの発火条件として確認済みの条件だけを `master_wrs_handover_rules.csv` に入れる。

### 誤判定リスク

- 「日新」を含む別会社・別ブランド・メモ文言に反応する。
- 修理依頼先としての日新と、WRS引き継ぎ対象としての日新を混同する。
- 日新の一部条件だけが対象なのに、全日新案件をWRS引き継ぎ対象にしてしまう。

## 2026-06-07 既存 `master_wrs_handover_rules.csv` 監査メモ

### 判定方式の確認

- `match_line` / `match_store_keywords` / `match_company_keywords` / `match_plan_keywords` / `match_case_keywords` のいずれかが一致すると identity 条件一致になる。
- `match_appliance_type` / `match_repair_type` は identity 一致後の絞り込み条件として働く。
- `match_case_keywords` は症状、メモ、製品、メーカーなど広い入力を含むため、短い語を入れる場合は誤発火リスクが高い。

### 明確に安全と判断したルール

- 京阪、ヤマダホームズ、ライフデザインカバヤ、福屋工務店、三井デザインテック、アイ工務店、MED Communications、キューハウ / Comfo home、住宅資材センター、大成有楽、相鉄不動産、オンレイ、ミツウロコヴェッセル、クリーンリバー、ケィ・マックインダストリー、FUTAEDA、木場家電住宅設備、松﨑電機 / エアコンのマツ。
- 根拠: 固有名詞が中心で、line/store/company の identity 欄に置かれている。通常案件の製品名やメモだけでは発火しにくい。

### やや広いが現状許容できるルール

- 住設駆けつけ: `駆けつけ` / `24h` / `24時間` / `365days` は広いが、`match_appliance_type=住設` で絞られている。
- コーナン住設 / ビーバートザン: `コーナン` は広いが、`match_appliance_type=住設` で家電案件は除外される。
- 電算システム案件: `電算` 単独ではなく `電算システム` で、かつ `match_appliance_type=住設` あり。
- フュディアル: 固有名詞だが住設条件で絞られている。
- Bosch: `match_case_keywords=Bosch` に置かれておりメーカー欄で発火する。Bosch製品は意図的な対象として既存テストで維持する。

### 注意が必要なルール

- SKY: 3文字の英字で短い。現状は line/store/company のみなので製品名・メーカー名だけでは発火しないが、回線名や販売店名に偶然 `SKY` を含む場合は発火する。
- 三城案件（メガネ）: `メガネ` が line/store/company に入っている。製品名だけでは発火しないが、販売店名や運営会社名に一般語として `メガネ` が入る場合は誤発火し得る。
- コジマ（CHIKYUJIN）: `コジマ` 単独で line/store/company 発火する。量販店名として通常案件に出る可能性があるため、業務上WRS対象が本当に全コジマ案件か確認が必要。
- チャオ: 短い固有名詞。別ブランドやメモ由来では発火しないが、販売店・運営会社に同名がある場合は発火する。
- WM案件（M停止）: `M停止` 単独で line/store/company 発火する現仕様。メモだけでは発火しないようテストで固定したが、入力欄を誤ると広い。
- ぽちる、トレス、三建: 固有名詞だが短め。現時点では既存登録を維持し、実案件で誤発火があれば追加条件を検討する。

### 今回追加したガード

- 製品名 `メガネ` 単独では三城案件に発火しないこと。
- 製品名/メーカー名/メモなど identity 欄以外の `SKY`、`コジマ`、`チャオ`、`M停止`、`電算`、`中古` がWRS発火しないこと。
- `M停止` が回線名に入る場合は現仕様どおりWM案件として発火すること。
- コーナン / ビーバートザンは住設なら発火し、家電なら発火しないこと。

### 変更保留

- 今回はCSV変更なし。`コジマ`、`メガネ`、`SKY`、`M停止` は削除・無効化せず、テストと本メモでリスクを明示する。
- 次に業務確認する場合は、`コジマ` 単独、`メガネ` 単独、`M停止` 単独が line/store/company に入ったケースを本当にWRS対象にするかを確認する。
