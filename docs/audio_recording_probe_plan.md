# 読み取り専用録音 非干渉検証計画

## 目的

WRT-helpr 本体へ録音機能を戻す前に、読み取り専用の入力ストリーム確認が現在の通話音声経路へ干渉しないことを、WRT 本体とは切り離して検証する。

この計画は録音機能の実装ではない。WRT-helpr の `app.py` から呼び出さず、通話開始ボタン、録音開始ボタン、停止ボタン、文字起こし UI も作らない。

## 禁止事項

- 本番通話中に実行しない。
- Windows の既定入力デバイス、既定出力デバイス、既定通信デバイスを変更しない。
- VB-CABLE、Voicemeeter、Jabra、Windows 音声設定を変更しない。
- WRT-helpr 本体から検証スクリプトを import しない。
- 録音ファイルを保存しない。
- 文字起こしを実行しない。
- `requirements.txt` に `sounddevice`、`soundfile`、`faster-whisper`、`numpy` など録音・文字起こし系依存を追加しない。

## 検証専用スクリプト案

検証ファイルを作る場合は `tools/audio_readonly_probe.py` のような WRT 本体外の場所に置く。初回は作成だけに留め、実行は通話が完全に止まっている時間帯に手動で行う。

想定する動作は以下だけに限定する。

1. 利用可能な入力デバイス一覧を表示する。
2. ユーザーが明示したデバイス ID だけを対象にする。
3. Windows 既定デバイスは変更しない。
4. 対象デバイスを読み取り専用 input stream として 1 秒以内だけ開く。
5. ストリームをすぐ閉じる。
6. 例外が出た場合は即終了し、再試行や自動切替をしない。
7. 録音データをファイル保存しない。

疑似コマンド例:

```powershell
python .\tools\audio_readonly_probe.py --list-devices
python .\tools\audio_readonly_probe.py --device-id 12 --duration-sec 1
```

検証スクリプトに録音保存オプション、文字起こしオプション、自動デバイス切替、既定デバイス変更処理を入れてはいけない。

## 成功条件

- デバイス一覧表示だけで Windows 音声設定が変わらない。
- 指定デバイスの input stream を短時間開いて閉じられる。
- 実行中も既存の通話音声の入出力経路が変わらない。
- 検証後も Windows 既定デバイス、VB-CABLE、Voicemeeter、Jabra の設定が実行前と同じ。
- WRT-helpr 本体を起動しても録音 UI、録音保存、文字起こし導線が表示されない。

## 失敗時の撤退条件

以下のいずれかが起きた場合、検証を停止し、WRT 本体への録音組み込みを進めない。

- 通話音声が聞こえない、相手に声が届かない、音量・入出力先が変わる。
- Windows の既定デバイスや通信デバイスが変わる。
- VB-CABLE、Voicemeeter、Jabra 側のルーティングや選択状態が変わる。
- input stream を開くだけでアプリ、Teams、ブラウザ通話、または既存の電話環境に影響が出る。
- 失敗時に自動復旧や自動切替が必要になる。

## 本体組み込み判断

WRT-helpr 本体へ録音機能を組み込む判断は、この非干渉検証が通り、実行ログと設定変更なしの確認が残ってから行う。

検証通過前に `app.py`、Streamlit UI、Teams 報告、ラクテル文生成、通話開始ボタンへ録音処理を接続しない。
