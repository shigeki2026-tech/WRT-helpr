# WRS引き継ぎ対象 保留メモ

作成日: 2026-06-06

## 目的

WRS引き継ぎ対象候補のうち、誤判定リスクがあり現時点では `data/master_wrs_handover_rules.csv` に追加しない対象を明文化する。後続作業で「未登録なのか、意図して保留しているのか」が分からなくなることを防ぐ。

このメモは仕様確認待ちの記録であり、判定ルール追加ではない。

## 保留対象

- 住設（賃貸・中古）
- 日新

## 住設（賃貸・中古）

### 保留理由

- 「住設」「賃貸」「中古」は語が広く、単独条件で拾うと通常の住設案件や賃貸系案件までWRS引き継ぎ対象になるリスクがある。
- どの項目で判定すべきか未確定。
  - 回線名
  - 保証プラン
  - 販売店
  - 運営会社
  - 案件区分
  - 製品分類
- WRS引き継ぎ条件として「日新」との関係確認が必要。

### 今後確認すべき条件

- 「住設（賃貸・中古）」は具体的にどの入力項目に現れるのか。
- WCS/保証管理画面上の正式表記。
- 日新案件だけが対象なのか。
- 住設かつ賃貸/中古なら全て対象なのか。
- 問い合わせと修理受付で扱いが違うのか。
- `action_type` は「受付報告」でよいのか。
- `note_template` に入れるべき注意文があるか。

### 追加する場合の想定ルール

- `match_appliance_type` に住設条件を置く場合は、必ず販売店・運営会社・保証プラン・案件区分などの明確な identity 条件と組み合わせる。
- 「賃貸」「中古」だけを `match_plan_keywords` や `match_case_keywords` に入れる場合は、通常案件への誤爆を避けるため、日新などの固有条件とセットにする。
- 受付報告以外の依頼種別がある場合は、`action_type` を業務確認後に設定する。

### 誤判定リスク

- 通常の住設案件が、賃貸物件・中古住宅などの文脈だけでWRS引き継ぎ対象になる。
- 保証プランやメモに「賃貸」「中古」が含まれるだけで対象化する。
- 問い合わせ一次受けと修理受付を混同する。

## 日新

### 保留理由

- 単独会社名として追加すると、日新という文字列を含む別会社/別案件に誤爆する可能性がある。
- 「住設（賃貸・中古）」とのセット条件なのか、日新単独条件なのか未確認。
- `master_vendor_rules.csv` 側の扱いと WRS引き継ぎ対象の扱いを混同しない必要がある。

### 今後確認すべき条件

- 正式会社名。
- 販売店名/運営会社名/保証プランのどこに出るか。
- 日新の全案件がWRS引き継ぎ対象か。
- 住設/賃貸/中古に限定されるか。
- 問い合わせ一次受けも対象か、修理受付のみか。

### 追加する場合の想定ルール

- 日新単独が対象なら、正式表記と表記揺れを確認して `match_store_keywords` または `match_company_keywords` に追加する。
- 住設（賃貸・中古）限定なら、日新の identity 条件に加えて `match_appliance_type` や保証プラン/案件区分の条件を併用する。
- `master_vendor_rules.csv` の修理依頼先判定とは別に、WRS引き継ぎの発火条件として確認済みの条件だけを `master_wrs_handover_rules.csv` に入れる。

### 誤判定リスク

- 「日新」を含む別会社・別ブランド・メモ文言に反応する。
- 修理依頼先としての日新と、WRS引き継ぎ対象としての日新を混同する。
- 日新の一部条件だけが対象なのに、全日新案件をWRS引き継ぎ対象にしてしまう。
