## 1. 回線名

回線名は「どの回線に入電したか」を示す事実入力です。

- 起動直後は空欄
- コピー/ペースト後も空欄のまま
- 保証プラン、製品情報、住設根拠からは自動入力しない
- OP/SVが最初に手動選択する
- 選択肢: 家電 / 住設（とそれに準じる回線名）
- 手動選択された回線名だけをラクテル見出し・Teams報告文などの業務出力に使う

旧仕様の「住設根拠が強ければ回線名を住設へ補正する」前提は廃止済みです。

---

## 2. 案件分類

案件分類は「案件内容・製品/保証の分類」です。回線名とは別物です。

| フィールド | 意味 | 選択肢 | 自動判定 |
|---|---|---|---|
| 回線名 | 入電した回線 | 家電 / 住設（等） | しない（手動のみ） |
| 案件分類 | 案件内容の分類 | 家電 / 住設（新築） / 住設（既築） | 可（保証プラン・製品情報から推定） |

この2つを混同しないでください。

旧フィールド名「家電/住設」は内部互換用として残っていますが、UIには表示しません。

---

## 3. アイ工務店ケース（回線名と案件分類の分離確認用）

コピー/ペースト直後:

- 回線名: 未選択
- 案件分類: 住設（既築）または住設（新築）へ自動判定される場合あり
- ラクテル見出し: `【●●回線に入電】`（回線名未選択時のプレースホルダー）

OP/SVが手動で住設回線を選択した後:

- 回線名: 住設
- ラクテル見出し: `【住設回線に入電】`

コピー直後から `【住設回線に入電】` になる前提でテスト・運用しないでください。

## 4. 修理方針判定

修理方針は `master_repair_type_rules.csv` を参照して判定します。

CSVには以下のフラグがあります。

| 列名 | 意味 |
|---|---|
| `manufacturer_required` | このルールの確定にメーカー確認が必要 |
| `model_required` | このルールの確定に型番確認が必要 |
| `manual_required` | このルールの確定に取扱説明書確認が必要 |

製品ごとの基本方針:

| 製品 | メーカー空欄時の修理方針 |
|---|---|
| 多機能便座 / 温水便座 / 温水洗浄便座 / シャワートイレ / ウォシュレット | 出張修理（メーカー不要） |
| 電子レンジ | メーカー確認が必要（`manufacturer_required=1`） |
| プリンター | 型番確認が必要（`model_required=1`） |
| 空気清浄機 | メーカー確認が必要（`manufacturer_required=1`） |
| プロジェクター（リコー以外） | メーカー確認・取説確認が必要 |
| 山善系 | 取説確認が必要（`manual_required=1`） |

## 5. トークスクリプト判定

スクリプトタグの基本判定は「回線名 + 案件分類」です。

- メーカーが未確定だけではスクリプト全体を未判定にしない
- 修理方針が未確定だけではスクリプト全体を未判定にしない
- 修理方針は補助条件として参照する

---

## 6. ラクテル用テキスト

| 状態 | ラクテル見出し |
|---|---|
| 回線名未選択 / 受電 | `【●●回線に入電】` |
| 回線名未選択 / 架電 | `【●●回線から架電】` |
| 家電回線 / 受電 | `【家電回線に入電】` |
| 家電回線 / 架電 | `【家電回線から架電】` |
| 住設回線 / 受電 | `【住設回線に入電】` |
| 住設回線 / 架電 | `【住設回線から架電】` |

「未選択回線」という表記は使いません。

修理受付の見出しは `【修理受付済み】` です（旧表記 `【修理受付】` は廃止）。

## 7. Teamsワランティ送信

- 見出し: `📣 Teamsワランティ送信`
- 対象: 全案件（引き継ぎ要否とは連動しない）
- 送信文形式: `{楽テルNO}　{回線名}　{確認内容}　ご確認お願いします`
- 未入力時のプレースホルダー: `楽テルNO未入力　●●　○○○○○○　ご確認お願いします`

送信可否の判定:

| 条件 | 結果 |
|---|---|
| 楽テルNO未入力 | 送信可（プレースホルダーで送信文を生成） |
| 回線名未選択 | 送信可（プレースホルダー `●●`） |
| 確認内容未入力 | 送信可（プレースホルダー `○○○○○○`） |
| chat_id 未設定 | **送信不可** |
| 送信スクリプト不可 | **送信不可** |
| send_mode 設定誤り | **送信不可** |

「楽テルNO / 回線名 / 確認内容の未入力だけで送信不可にしない」が原則です。

## 8. 修理依頼書メモ追記候補

- selectboxで定型文を1つ選ぶ方式
- 「この文言を追記」で修理依頼書メモにのみ追記
- 追加候補リスト方式には戻さない
- `condition_text` は本文に直接追記しない

---

## 9. 終話後処理タブ

- 主役は「記録文（ラクテル用テキスト・Teams報告文・修理依頼書メモ）」
- 送付テンプレート・拠点、修理拠点詳細、Driveリンク等は補助情報として扱う
- 旧対応履歴テンプレは通常表示しない。必要時のみ折りたたみ（`対応履歴テンプレ（旧形式・必要時のみ）`）で開く

---

## 10. 判定タグ

画面上部の4タグは以下です。

- 受付可否
- 修理方針
- 拠点対応
- スクリプト

起動直後は4タグすべて `未判定` です。不足ありは赤系、要確認は黄・橙系、確定したタグのみ緑・青系の確定色にします。

---

## 11. 次にやること / 次に確認すること

初期状態では大量の不足項目を表示しません。

- 回線名を選択
- 保証情報を貼り付け

コピー/ペースト後は、通話中に必要な確認項目を最大5件まで表示します。詳細不足項目は `不足項目の詳細を開く` に折りたたんで表示します。

表示文言は短くしています。

- `保証開始日・保証終了日を確認してください` → `保証期間を確認`
- `都道府県または住所を確認してください` → `住所/都道府県を確認`
- `修理方針が要確認のため、取説または過去履歴を確認してください` → `修理形態を確認`
- `スクリプトURL未登録のため、正式Excelを手動参照してください` → `正式Excelを参照`
- `終話後に担当へエスカレーションして拠点確定` → `終話後に拠点確認`
