# WRT-helpr MVP v0.1 操作・導入マニュアル

このマニュアルは、修理受付支援ツール **WRT-helpr MVP v0.1 現場テスト版** を別PCへ導入し、現場テストで使うための手順書です。

対象者:
- SV / ASV
- 修理受付業務の確認担当
- 現場テスト協力者

このツールは、正式トークスクリプト本文の代替ではありません。正式な案内は必ず先方管理の最新版スクリプトを参照してください。

---

## 1. このツールでできること

WRT-helpr は、修理受付時に以下を支援します。

- 保証画面からコピーしたテキストの抽出
- 保証開始日・終了日による受付可否判定
- 製品・メーカー・都道府県のリスト入力
- 回線名の手動選択
- 家電 / 住設判定
- 出張修理 / 持込修理 / 要確認判定
- 保証対象外時の概算費用判定
- 金額案内可否判定
- データ消去同意要否判定
- 参照すべき正式スクリプトのシート名・パート名表示
- 判定タグと判定診断パネルによる不足項目表示
- 次にやること / 次に確認すること表示
- 終話後の対応履歴テンプレ作成

## 1.1 最新仕様メモ

### 回線名と案件分類

| フィールド | 意味 | 選択肢 | 自動入力 |
|---|---|---|---|
| 回線名 | 入電した回線 | 家電 / 住設（等） | しない（手動のみ） |
| 案件分類 | 案件内容の分類 | 家電 / 住設（新築） / 住設（既築） | 可 |

- 回線名: コピー情報・保証プラン・住設根拠からは自動入力しません。起動直後もコピー/ペースト後も空欄のままです。OP/SVが最初に手動選択します。
- 案件分類: 保証プランや製品情報から自動判定してよい項目です。回線名とは別物として扱います。

手動選択された回線名だけを、ラクテル見出し・Teams報告文などの業務出力に使用します。

### アイ工務店ケース

コピー/ペースト直後は、アイ工務店の住宅設備プランなど住設根拠が強い場合でも、回線名は未選択です。ラクテル見出しは `【●●回線に入電】`（回線名未選択時のプレースホルダー）になります。

OP/SVが手動で住設回線を選択した後に限り、回線名は住設となり、ラクテル見出しは `【住設回線に入電】` になります。

### 判定タグ

起動直後の4タグはすべて `未判定` です。

- 受付可否
- 修理方針
- 拠点対応
- スクリプト

不足ありは赤系、要確認は黄・橙系、確定したタグのみ緑・青系で表示します。

### 次にやること / 次に確認すること

初期状態では大量の不足項目を表示せず、以下だけを表示します。

- 回線名を選択
- 保証情報を貼り付け

コピー/ペースト後は、通話中に必要な確認項目を最大5件まで表示します。詳細な不足項目は `不足項目の詳細を開く` に折りたたんで表示します。

### 最新テスト状況

- 最新commit: `1470324 update`
- `python -m pytest -v`: `557 passed`

## 3. 初回セットアップ

PowerShellを開き、展開したフォルダへ移動します。

```powershell
cd C:\WRT-helpr
```

Pythonが使えるか確認します。

```powershell
py --version
```

Pythonのバージョンが表示されればOKです。

仮想環境を作成します。

```powershell
py -m venv .venv
```

PowerShellの実行ポリシーで止まる場合に備え、以下を実行します。

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

仮想環境を有効化します。

```powershell
.\.venv\Scripts\Activate.ps1
```

必要なライブラリをインストールします。

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

起動したら、まず以下を確認します。

- アプリ画面が表示される

- 保証開始日・保証終了日に今日の日付が勝手に入っていない

## 6. 基本操作の流れ

### STEP 1: コピー情報を貼り付ける

保証管理画面などから情報をコピーし、左側のコピー情報取り込み欄へ貼り付けます。

その後、抽出・反映ボタンを押します。

抽出される主な項目:

- プラン
- 保証開始日
- 保証終了日
- お客様コード
- お客様名
- 電話番号
- 郵便番号
- 住所
- 都道府県
- WRT-NO
- 商品価格
- ジャンル
- 分類
- シリーズ
- メーカー
- 型番
- 販売店

---

### STEP 2: 受付情報フォームを確認する

中央の受付情報フォームを確認します。

特に重要な項目:

- 保証開始日
- 保証終了日
- 都道府県
- 製品
- メーカー
- 補足条件・費用判定メモ
- 販売店
- 案件分類

日付はカレンダー入力です。
コピー抽出で日付が取れた場合は、自動でカレンダーへ反映されます。

日付が分からない場合は `未確認` にしてください。

---

### STEP 3: 判定結果を見る

右側の判定結果を確認します。

確認する順番:

1. 保証期間判定
2. 判定診断
3. 次に聞くこと
4. 修理形態
5. 概算費用
6. 参照スクリプト
7. 修理拠点候補
8. 対応履歴テンプレ

保証期間判定が `受付不可` の場合は、概算費用よりも受付不可理由を優先してください。

## 7. 保証期間判定

保証開始日・保証終了日から、受付可否を判定します。

| 状態 | 意味 | 対応 |
|---|---|---|
| 保証開始日前 | まだWRT保証開始前 | メーカー保証または販売店・メーカー窓口へ誘導 |
| 保証期間内 | WRT保証期間内 | 通常の受付判定へ進む |
| 保証期間終了 | WRT保証終了後 | 受付不可 |
| 保証期間未確認 | 日付不足・未確認 | 保証開始日・終了日を確認 |

注意:
- 日付未入力時に今日の日付は自動入力されません。
- 未確認チェックON、またはクリア時は保証期間未確認になります。

---

## 8. 判定タグ・判定診断パネル

画面上部の判定タグは、受付可否・修理方針・拠点対応・スクリプトの4つです。起動直後はすべて `未判定` とし、不足ありは赤系で表示します。コピー/ペースト後も、必要情報が揃ったタグだけを確定色にします。

判定診断パネルは、何が不足しているか、何を次に確認すべきかを表示します。

診断対象:

- 保証期間判定
- 概算費用判定
- 参照スクリプト判定
- 修理形態判定
- 修理拠点判定

表示される内容:

- 判定エリア
- 状態
- 影響度
- 理由
- 不足項目
- 次に確認すること

不足項目には、該当フィールドへ移動するリンクが表示されます。

例:

```text
不足項目:
- メーカー欄へ移動
- 補足条件欄へ移動
```

## 9. 次にやること / 次に確認すること

初期状態では、OPがすぐ行う2件だけを表示します。

例:

```text
次にやること
1. 回線名を選択
2. 保証情報を貼り付け
```

コピー/ペースト後は、通話中に必要な確認項目を最大5件まで短いカード形式で表示します。

例:

```text
[通話中] メーカーを確認
[通話中] 型番を確認
[通話中] 住所/都道府県を確認
[終話後] 終話後に拠点確認
```

詳細な不足項目は通常画面に常時展開せず、`不足項目の詳細を開く` に折りたたんで表示します。

## 10. 概算費用判定の注意

概算費用には以下の状態があります。

| 状態 | 意味 |
|---|---|
| confirmed | 概算費用が確定候補として表示可能 |
| pending | 追加確認が必要 |
| escalation | エスカレーション注意 |
| unavailable | 金額案内不可 |

重要な例:

- エアコンでメーカー未入力の場合、金額は表示しません。
- ダイキンエアコンは家庭用 / 業務用の確認が必要です。
- パソコンは国内メーカー / 海外メーカーで概算が変わります。
- 給湯器のみでは、ガス / 石油 / ハイブリッドの別を確認するまで金額を確定表示しません。
- ビックカメラ / ソフマップ案件は金額案内不可です。

## 11. 参照スクリプト

アプリは正式スクリプト本文を保持しません。

表示するのは以下だけです。

- シート名
- 該当パート
- 補足確認
- 参照リンク

参照リンクは `data/master_script_links.csv` で管理します。

URLが未登録の場合は、シート名・該当パートをもとに正式資料を手動で確認してください。

## 12. 対応履歴テンプレ

画面下部に対応履歴テンプレが表示されます。

内容を確認し、必要に応じてシステムへ貼り付けます。

注意:

## 13. 終話後処理タブの使い方

終話後処理タブは「記録文の作成」が主役です。ラクテル用テキスト・Teams報告文・修理依頼書メモを作成します。送付テンプレート・拠点詳細・Driveリンク等は補助情報です。

操作手順:

1. `通話中判定` タブで受付情報を入力します。
2. `終話後処理` タブへ移動します。
3. テンプレート候補が表示されているか確認します。回線名が未選択の場合は、先に手動で回線名を選択します。
4. 楽テルNOを入力します。
5. 日程調整時の連絡先を確認します。
6. 依頼票メモ備考を確認します。
7. Teams報告文を生成します。
8. 送信先チャット名と報告文の内容を確認します。
9. 必要に応じて `送信内容と送信先を確認しました` にチェックします。
10. `Teamsチャットへ送信` を押します。

### 旧対応履歴テンプレ

旧形式の対応履歴テンプレは通常非表示です。必要な場合のみ `対応履歴テンプレ（旧形式・必要時のみ）` を展開してください。

### 📣 Teamsワランティ送信

全案件でワランティ報告チャットへ送信します（引き継ぎ要否とは連動しません）。

- 送信文: `{楽テルNO}　{回線名}　{確認内容}　ご確認お願いします`
- 未入力項目はプレースホルダーで送信文を生成します。楽テルNO・回線名・確認内容の未入力だけで送信不可になりません。
- 送信不可になるのは、chat_id 未設定・送信スクリプト不可など本当に送れない場合のみです。

Teams送信を使う前の確認:

- 画面に表示される送信先チャット名が正しいことを確認してください。
- 報告文には個人情報が含まれる可能性があるため、送信先ミスに注意してください。
- `config/teams_config.json` の `warranty_chat_id` が未設定の場合、送信ボタンは使えません。
- 送信に失敗した場合は、Teams報告文をコピーして手動投稿してください。

注意事項:

- Teamsへ完全自動送信する機能ではありません。必ず内容確認チェックを行ってから送信します。
- 報告文には個人情報が含まれるため、送信先または貼り付け先を間違えないでください。
- テンプレート候補が意図と違う場合は、必ず手動で確認してください。

## 14. マスタ管理タブ

マスタ管理タブでは、CSVマスタの内容を確認できます。

主なCSV:

| CSV | 役割 |
|---|---|
| master_product_alias.csv | 製品名の表記ゆれを正規化 |
| master_repair_type_rules.csv | 修理形態判定 |
| master_cost_rules.csv | 概算費用判定 |
| master_vendor_rules.csv | 修理拠点候補判定 |
| master_manufacturer_groups.csv | メーカーグループ |
| master_area_groups.csv | NTT東西エリア |
| master_script_links.csv | 参照スクリプトリンク |

CSVを更新した後、古い判定が残る場合は `CSVキャッシュをクリア` を押してください。

## 15. 現場テストの進め方

最初は正式運用ではなく、現場テストとして使ってください。

推奨手順:

1. `docs/demo_cases.md` の5ケースを貼り付けて確認
2. `docs/manual_checklist.md` に沿って目視確認
3. 実コピー文を1〜3件貼って確認
4. 違和感を `docs/field_test_feedback.md` に記録

記録すべき内容:

- 誤判定
- 分かりにくい表示
- 入力しづらい項目
- 足りない判定
- 追加したい項目
- 優先度

保証開始日・終了日の未確認チェックやクリア操作を確認してください。

## 17. 現場テストで確認するポイント

最低限、以下を確認してください。

- 初見でどこに何を入力するか分かるか
- 次に聞くことSTEPが役に立つか
- 警告が多すぎないか
- 保証期間NG時に受付不可が最優先で見えるか
- エアコン・給湯器で誤って金額案内しそうにならないか
- 履歴テンプレが実務で使える長さか
- スクリプト参照欄が分かりやすいか
